# Evaluation rules

The official PDFs were inspected. The authoritative Russian checklist is in `config/official_checklist_v1.json`; `scripts/create_official_seed.py` regenerates it. C01–C07 weights are 10, 15, 20, 20, 15, 15, 5. C04 accepts only 0/5/10/15/20 and C06 only 0/4/7/10. Only C02/C03/C04/C07 allow N/A, under their configured exact conditions. C08 is a yes/no gross-violation flag with no numeric score or weight.

For applicable weighted criteria, earned = weight × raw score / maximum score. The overall total is `100 × sum(earned) / sum(applicable weights)`. N/A weights are excluded; a zero denominator returns null. Calculations use `Decimal` with 50-digit working precision and no intermediate point rounding. The final two-decimal result uses ROUND_HALF_UP; this tie policy is an engineering choice because the PDF does not specify ties. Section scores use the same normalization within each section; only the global denominator determines the official overall. Flags do not change the overall score.

The validator checks metadata, active criterion coverage, uniqueness, allowed answers/scales, justified permitted N/A, existing message IDs, checked-span order and exact original quotes. Missing actions require a checked span. All negative binary judgments require one as well. Deterministic checks cannot prove that a semantic explanation is correct or that an N/A rule actually applies; ambiguous cases need human review. Financial advice that relies on unavailable tariff/policy references must be provisional with fact-verification and review flags. C04 content and C06 communication are distinct.

The three-minute first-response threshold, tags and attachments are excluded. Bot/system messages are context; operator behavior is evaluated. Transcript text is untrusted data in the provider prompt, separated from trusted configuration by the SDK system instruction. This separation and structural validation reduce injection risks but do not constitute a semantic security guarantee.

Reviewer decisions are validated against the same immutable checklist and evidence rules and recomputed in a transaction. Original AI results and individual original judgments remain unchanged. Confirmation retains the current finalized judgment; changes require a replacement judgment and a reason. Repeat appeals after a decision are allowed, and each decision remains in history.
